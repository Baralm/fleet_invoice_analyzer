Fleet Invoice Analyzer: Architecture

FastAPI service that turns a repair-shop invoice (PDF/TXT) into schema-valid JSON of billed line items, with totals reconciled in code.

Azure AI Content Understanding

Analyzer LineItemExtract, based on prebuilt-document + GPT-5. OCR + layout, then the field schema acts as the prompt (incl. excluded_items).R2

EXTRACTION_MODE

azure mode · extract_with_azure()

  • POST …:analyzeBinary → 202 + placeholder
  • Poll operation-location until Succeeded (same host only, honours Retry-After, 90 s timeout)
  • Returns fields + usage (pages, tokens)

local_demo mode (offline)

  • Read text (pypdf for PDFs)
  • Route by vendor: Great Lakes, Harborline, Desert Sun, or ITEM| format
  • Regex/layout parsers keep billed rows onlyR2
  • Unknown layout → error, never fake data

Normalize

normalize_analyzer_result()
  • Unwrap Azure fields
  • _to_number: "$1,040.58" → 1040.58; text → 502R1
  • Excluded items → notesR2

Reconcile

reconcile()
  • Decimal, round to cents
  • Σ items vs subtotal
  • subtotal + tax vs total
  • Mismatch → flag + note, never "fixed"R3

Schema gate

app/schema.py (Pydantic)
  • extra="forbid"
  • line_type ∈ 5 values
  • amount required
  • ISO service_dateR1

Offline tooling: set-up, evaluation, tests

Analyzer set-up

scripts/create_analyzer.py
Reads azure/analyzer_definition.json (field schema: header, line_items, excluded_items, totals) and PUTs it to Azure (--replace overwrites), then polls until ready.

EvaluationR4

scripts/evaluate.py --mode azure|local_demo
Sends all 12 sample files through the real /extract, scores against samples/labels.json: line-item P/R/F1, headers, totals, reconciliation flag, leaked unbilled items → evaluation/results_*.json.

Test documentsR4

samples/ · scripts/make_sample_pdfs.py
3 provided invoices (inv_07–09) + 3 created ones (inv_10 Pinecrest: declined rows, inv_11 Ironbridge: wrong subtotal, inv_12 Northstar: 2 pages, 2 taxes, deposit), each as .txt and .pdf.
